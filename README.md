# 矩阵乘法四层实现：从 Verilog 到 CUDA

2026 秋《数字媒体程序设计》第 03 讲实验作业。

同一个 3×3 矩阵乘法，在四个层次各写一遍：Verilog（电路）、汇编（机器码）、C（顺序）、CUDA（线程），用来说明同一算法在不同层的代价差异。

## 测试数据与标准答案

```
A = {{1,2,3},{4,5,6},{7,8,9}}
B = {{9,8,7},{6,5,4},{3,2,1}}

C = A × B = {{30, 24, 18},
             {84, 69, 54},
             {138,114, 90}}
```

四份实现的结果必须与这个手算答案逐位一致。

## 文件说明

| 文件 | 层 | 说明 |
|---|---|---|
| `matmul.c` | C | 三重循环 i-j-k，顺序执行 |
| `matmul_O0.s` | 汇编 | gcc 13.2 `-O0` 的实际输出，155 行，内层是 mov → imul → add |
| `matmul_O2.s` | 汇编 | gcc 13.2 `-O2` 的实际输出，104 行，指针递增寻址 |
| `matmul.v` | Verilog | `generate` + `genvar` 展开 9 个乘加通路，纯组合逻辑 |
| `matmul_tb.v` | Verilog | 测试激励，单独用于 EDA Playground 一类双框编辑器 |
| `matmul_run.v` | Verilog | 上面两个文件合并版，供 OneCompiler 这类单框编辑器使用 |
| `matmul.cu` | CUDA | 一个线程算一个 `C[i][j]`，`threads(32,32)`、`blocks(1,1)` |

## 关键结论

**-O0 与 -O2 的实测对比**（gcc 13.2，x86-64）：

| 选项 | 汇编行数 | imul | add | mov |
|---|---|---|---|---|
| `-O0` | 155 | 1 | 24 | 76 |
| `-O2` | 104 | 1 | 10 | 26 |

`-O2` 并没有把内层循环展开成多组 imul/add（imul 始终只有 1 条），它做的是把数组下标改成指针递增（`add rax,4` / `add r8,12`）并把循环变量放进寄存器，所以 mov 从 76 条降到 26 条。**编译器优化省的是搬运，不是计算。**

**四层对照**：

| 维度 | Verilog | 汇编 | C | CUDA |
|---|---|---|---|---|
| 并行粒度 | 组合逻辑同时翻转，9 个乘法器并排 | 无并行 | 无显式并行，三重循环 | 线程级，一线程一元素 |
| 数据位置 | 线网与寄存器 | 寄存器 / 内存 | 栈 / 堆 / 内存 | 全局显存 / 共享内存 |
| 谁在调度 | 无调度器，电平驱动 | CPU 顺序取指 | CPU 顺序执行 | GPU 线程调度器分配 warp |

## 怎么跑

**C / 汇编**：`https://godbolt.org`，语言选 C，编译器 x86-64 gcc 13.2，编译选项填 `-O0` 或 `-O2`。

**Verilog**：`https://onecompiler.com/verilog`，粘贴 `matmul_run.v`，点 Run。预期输出：

```
30 24 18
84 69 54
138 114 90
```

**CUDA**：`https://godbolt.org`，语言切到 CUDA，编译器选 NVCC 12.9.0。在线环境只能编译出 PTX，不能真正在 GPU 上运行；本机也没装 CUDA toolkit，所以本仓库只验证到编译与指令层。

## 踩过的坑

1. **非压缩数组端口**：`input signed [7:0] a[0:2][0:2]` 是 SystemVerilog 写法，Verilog-2001 的 Icarus 不支持。本仓库改成扁平向量（9 个 8 bit 拼成 72 bit），内部用 `generate` 按位切片。
2. **在线平台**：EDA Playground 从校园网访问不稳定；JDoodle 免费额度要登录且有人机验证；最后用 OneCompiler（免登录）跑通。
3. **CUDA 在线运行**：网上流传的 cudaforces 域名已跳到 swforces（刷题判题站），不是 CUDA 模拟器。
